## 2026-06-30 - MT5 Execution Alignment Slice

- Investigated SP500 M1, NAS100 M15, and EURUSD H1 MT5 deltas against the current comparison matrix:
  - SP500 M1: reference 512 trades / 39255.92 net profit vs platform 239 trades / -4800.04.
  - NAS100 M15: reference 597 trades / 43791.14 net profit vs platform 319 trades / -5598.22.
  - EURUSD H1: reference 492 trades vs platform 71 trades.
- Root causes isolated:
  - Execution model: the native event engine recognized `stop_loss` but not the strategy-standard `sl_price`, so tuple-style strategies could miss stop placement and risk sizing unless they duplicated aliases.
  - Strategy logic/execution timing: `IntradayVolatilityBreakout.mq5` evaluates the just-closed M15 candle at the opening tick of the next M15 candle. The converted strategy now emits candle-close entries one source bar earlier so the platform's next-open execution lands on the same timestamp.
  - Strategy logic: the intraday conversion calculated entry `direction` but did not return it in `indicators_dict`; native tuple-style execution could therefore default entries to LONG in regenerated runs.
  - Data/artifact model: `reports/strategy_comparison_backtest_*_after_align_20260623.trades.json` are tagged `Volatility Breakout`, while the reference XLSX files are `IntradayVolatilityBreakout.mq5`. The comparison matrix still consumes these static artifacts, so regenerated matrix metrics do not move until the platform artifacts are rerun from matching strategy/data inputs.
  - EURUSD H1 residual: the MT5 EA always uses M1 and M15 internals for entry levels/confirmation even when the tester period is H1. The current platform artifact only has H1 timestamps (`18:00`/`19:00`), while MT5 entries cluster at `16:45`..`18:00`; matching this requires multi-timeframe data injection or regenerating from M1/M15 execution data.
- Code changes:
  - `runner/engine.py`: treats `sl_price` as a native stop-loss alias and `tp_price` as a take-profit alias.
  - `strategies/intraday_volatility_breakout/intraday_volatility_breakout.py`: returns `direction`; aligns candle-close signal bars to next-open execution; shifts `sl_price` with the execution signal.
  - Added focused regression coverage for native `sl_price` stop/risk sizing and M15 candle-close signal alignment.
- Before/after matrix:

  - After `python scripts/compare_strategy_metrics.py --output reports/strategy_metric_comparison_matrix_20260630.json`: numeric values unchanged because the matrix reads the existing static platform artifacts; only `generated_at` changed.
